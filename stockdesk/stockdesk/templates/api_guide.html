INTEGRATION & OPERATIONS

Keep the contract explicit.

The browser and API use the same stock services.

Open API schema

Authenticate before making changes

Read GET /api/session and keep its cookie and csrf_token. Send that token in the X-CSRF-Token header with POST /api/login. Login returns a fresh token; use it for subsequent writes.

Stock writes need an idempotency key

Send a new Idempotency-Key for each intended stock change. Retry the same request with the same key after a network interruption. A changed payload under an existing key is rejected.

Primary endpoints

/api/products and /api/inventory
Catalog entries and paginated warehouse balances.
/api/movements
Receipts, issues and atomic warehouse transfers.
/api/orders
Draft orders, order lines, submission and partial receipts.
/api/counts
Warehouse snapshots, physical counts and version-checked adjustments.
/api/reconcile
Administrator-only comparison of balances and the movement ledger.

Operating limits

This release uses whole units, a maximum balance of 1,000,000,000, at most 500 lines per purchase order or stock count, and 10,000 rows per CSV export. It is one-business software, not multi-tenant hosting. Costs use integer minor units and are not an accounting valuation.

Before a live deployment

Read docs/OPERATIONS.md and SECURITY.md. Configure HTTPS, trusted hosts, a private session secret and tested backups. The full API request examples are in docs/API.md.

Project origin

The initial code, tests and documentation were AI-generated in a single session. See AI_ASSISTANCE.md for the authorship record and licensing-submission limitations.
