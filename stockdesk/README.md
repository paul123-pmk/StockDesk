# StockDesk

**A working, local-first inventory application for one small business.**
Track products across warehouses, receive purchase orders, reconcile physical
counts, and retain a record of every stock adjustment. The browser interface and
JSON API use the same transaction and authorization services.

## Start on Windows PowerShell

Install Python 3.11 or newer. Git is needed only when restoring the bundle or
working with repository history. The commands below are run from the project
root. Installing dependencies requires access to a Python package index.

To restore the history-bearing delivery first:

```powershell
git clone .\stockdesk.bundle stockdesk
cd stockdesk
```

For the source ZIP instead, extract it and open a terminal in its `stockdesk`
folder. Then use the same setup commands:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m stockdesk init
.\.venv\Scripts\python.exe -m stockdesk create-user --username owner --role admin
.\.venv\Scripts\python.exe -m stockdesk serve
```

Choose your own password when prompted; it is not echoed or passed as a command
argument. Open **http://127.0.0.1:8000** and sign in. No default account or password
is shipped. Activation is not required because these commands call the virtual
environment's Python directly.

The default database and randomly generated local session key live in `instance/`.
Do not commit that directory. Stop the server with Ctrl+C.

## Try the workflows with fictional data

Before entering your own catalog, stop the server and run:

```powershell
.\.venv\Scripts\python.exe -m stockdesk demo
.\.venv\Scripts\python.exe -m stockdesk serve
```

The command accepts only an empty catalog and creates 12 fictional products,
two warehouses, three suppliers, sample movements, a partial purchase order,
and a draft stock count. It creates no additional user accounts. All examples
are labeled synthetic; they are not genuine trading records or traction.

A useful first walkthrough:

1. Open **Inventory** to compare stock by warehouse. Receive stock, issue it,
   and transfer it between locations from **Movements**.
2. Create a purchase order, add lines, submit it, then receive some or all of
   each line. Submitted quantities cannot be silently edited.
3. Start a stock count, enter physical quantities, and post it. A count whose
   underlying stock changed must be cancelled and started again.

The source of truth is the movement ledger. A warehouse balance is a maintained
summary; `check` compares it with that ledger.

## Included behavior

| Area | Implemented behavior |
|---|---|
| Catalog | Unique product codes, edit-version conflicts, archive/reactivate, warehouse and supplier records |
| Inventory | Receipts, issues, atomic two-location transfers, no negative stock, idempotent stock operations |
| Purchasing | Draft lines, submission, partial/full receiving, over-receipt checks, state-aware cancellation |
| Stock counts | Versioned snapshots, partial input, stale-count rejection, atomic adjustments |
| Accounts | Admin/operator/viewer roles, password resets, session revocation, last-admin protection |
| Reports | Low stock, operational stock value, movement history, admin audit and reconciliation, snapshot-consistent CSV |
| Operations | Database initialization, interactive account setup, backup validation, restore instructions, health endpoint |

Administrators manage catalog and accounts. Operators can move stock and manage
orders/counts. Viewers can read operational data and export inventory. Audit,
reconciliation, and account-management endpoints are administrator-only.

## Verification

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest --cov=stockdesk --cov-report=term-missing
.\.venv\Scripts\python.exe -m compileall -q stockdesk scripts
.\.venv\Scripts\python.exe scripts\repository_checks.py --history
.\.venv\Scripts\python.exe scripts\repo_metrics.py
```

Coverage includes branches and has an 85% combined minimum in `pyproject.toml`.
Tests cover domain validation, real temporary SQLite databases, rollback,
concurrent writes, idempotency, API and HTML flows, session revocation, CSRF,
escaping, exports, CLI commands, and restoring a verified backup. Tests use
randomly generated temporary credentials, not bundled working passwords.

`repository_checks.py` is a **limited signature and file-policy check**, not a
complete secret detector or a personal-data audit. A passing result is not a
security certification. The separate delivery verification report records what
was actually run and what could not be run. GitHub Actions YAML is supplied;
no hosted workflow run or badge is claimed.

An optional `scripts/browser_smoke.py` exercises the real browser with a
throwaway database. It additionally requires Playwright and Chromium. The
current environment blocked browser navigation to loopback, so that script's
full workflow was not verified here; offline page renders are not a substitute.

## Deliberate limits

One organization, one currency label, whole-number units, and a SQLite database
on local disk. This is not an accounting, tax, payments, or multi-tenant system.
Stock value is quantity multiplied by the product's currently configured unit
cost, not FIFO, weighted-average costing, or a general ledger. Currency defaults
to KES but is only a display label. There are no exchange-rate calculations.

No MFA, email delivery, password self-service, barcode hardware integration,
batch/expiry tracking, supplier contact records, mobile app, or external API
tokens are included. Counts and purchase orders support at most 500 lines;
CSV exports support at most 10,000 rows. Large installations need profiling,
operational controls, and architecture review before deployment.

Use the default loopback-only server for evaluation. Public deployment requires
TLS, explicit trusted hosts, protected runtime storage, rate limiting at the
edge, a dependency review, and a qualified security review. See
[SECURITY.md](SECURITY.md) and [docs/OPERATIONS.md](docs/OPERATIONS.md).
